## Context

The statistics site is a static page backed by JSON generated by `BasketStatisticsExportService`. Navigation and rendering live in `docs/index.html`, `docs/app.js`, and `docs/styles.css`. Putting data is currently exported once per player and includes complete-round overall and yearly aggregates for C1x, C2+, best C1x rounds, most C2+ rounds, and longest throw-ins.

The leaderboard needs to compare many players and years. Loading every personal snapshot in the browser would create unnecessary requests and duplicate ranking logic, so the exporter should produce one aggregated leaderboard asset.

## Goals / Non-Goals

**Goals:**

- Add the Leaderboards top-level view and its five category tabs.
- Export one leaderboard dataset containing Overall and year-scoped results.
- Preserve the exporter’s complete-round eligibility, weighted C2+ comparison, best-C1x tie rules, and longest-throw-in exact-distance rules.
- Make ties, ranking boundaries, and contextual tooltips deterministic and accessible.

**Non-Goals:**

- Changing putting classification, round completeness, or existing Personal stats calculations.
- Adding divisions, gender filters, course filters, pagination, or user-configurable leaderboard sizes.
- Adding tooltips to C1x or C2+ per round values.

## Decisions

### Aggregate in the exporter

Add leaderboard data to a dedicated generated JSON asset and expose its relative path from the statistics manifest. Build it from the same `PuttingPlayerBuilder` aggregates used by personal snapshots, so the UI does not recalculate statistical rules and does not fetch all player files.

The payload should contain category entries grouped by scope (`overall`, `2025`, etc.). Each entry should include the player display name, rendered value, an underlying comparable value, and only the category-specific tie/tooltip metadata needed by the UI.

### Define category metrics

- **C1x** uses each player’s overall complete-round C1x success percentage. The value preserves the existing percentage and successful/total presentation, but has no tooltip. Ranking uses the unrounded percentage.
- **C2+ per round** uses the existing average weighted C2+ successes per complete round. It has no occurrence suffix and no tooltip. Ranking uses the unrounded average.
- **Most C2+ in a round** uses the existing weighted maximum (`C2+ successes / expected holes`) and displays the existing rounded count. Its occurrence count is the secondary ranking criterion. Matching round descriptors provide the tooltip.
- **Best C1x round** uses the existing best-round percentage and existing successful/total display. Its number-of-matching-rounds count is the secondary ranking criterion. Matching round descriptors provide the tooltip.
- **Longest throw-in** uses the exact maximum distance in feet for ranking, displays the existing rounded whole-meter value, and uses exact-distance occurrence count as the secondary ranking criterion. Matching hole occurrences provide the tooltip.

### Rank and render ties

Sort each category by its primary comparable value descending, then by its category-specific occurrence count descending where applicable, then by player name alphabetically. Players with equal primary and secondary ranking values share a place (`T1`, `T2`, etc.); the next place uses competition ranking (`3` after two players tied at `T1`). If the tenth place is tied, retain every player sharing that rank. A player appears at most once in a category and scope.

Use the unrounded values for ranking and tie equality. Use the established display rounding only for the rendered value.

### Represent round-length effects explicitly

Extend the Most C2+ round context with expected hole count. The exporter marks a leaderboard result when the weighted round-length calculation affects the player’s placement relative to raw C2+ counts or other candidates. The UI appends `*` to that displayed value and includes `Round with N holes` in the existing tooltip context. Results unaffected by round length do not receive the asterisk.

### Keep year selection predictable

The year selector contains `Overall` followed by every calendar year from 2025 through the current calendar year, even if a year has no qualifying entries. `Overall` is selected when the Leaderboards view is first opened. Selecting a category or year rerenders the existing exported data without a network request.

## Risks / Trade-offs

- [Generated data can become stale] → Regenerate the static export as part of the existing export workflow and preserve the manifest path so missing assets produce the page’s normal error message.
- [A rounded display value can hide distinct underlying rankings] → Store and sort by unrounded comparable values while rendering the established rounded format.
- [Variable round lengths make Most C2+ less intuitive] → Preserve the existing weighted calculation, show an asterisk only when it affects placement, and explain the actual hole count in the tooltip.
- [Old exports lack leaderboard data] → Hide or show an unavailable message for the Leaderboards view when the manifest does not provide the new asset; existing views remain usable.
